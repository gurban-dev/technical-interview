# How to Approach Coding Interviews

## 1. Work Collaboratively with the Interviewer

Behave in a friendly, professional manner. Treat the interviewer as someone you are working with on the same team to solve a problem.

Communicate your reasoning throughout the interview rather than silently trying to find the answer.

## 2. Understand and Clarify the Problem

Do not jump straight into coding. First, paraphrase the question in your own words and confirm that you understand what the interviewer is asking.

Ask at least 2 or 3 relevant clarifying questions about the input, expected output, constraints, and edge cases.

For example, if asked to reverse an array of integers, consider asking:

- Can the array be empty?
- Can it contain negative numbers, zeros, or duplicates?
- How large can the input be?
- Is the input guaranteed to be an array, or could it use another data structure?
- Is the input sorted?
- Is there always a valid solution, or does it depend on the input?
- Are there any time or space complexity requirements?

Adapt your questions to the problem. For linked lists, for example, clarify whether the function should return the head of the resulting list or something else.

## 3. Visualize the Problem and Work Through Examples

Draw the problem on paper or a whiteboard when helpful. Visualizing arrays, pointers, linked lists, trees, and graphs can make their relationships easier to understand.

Ask for test cases if none are provided. Walk through each example verbally, explaining why the expected output follows from the input.

Create additional test cases to cover edge conditions, such as:

- Empty input, if permitted.
- A single element.
- Negative numbers and zeros.
- Duplicate values.
- Minimum and maximum input sizes.
- Missing solutions, if applicable.

## 4. Develop an Algorithm Before Coding

Discuss your approach with the interviewer before implementing it. This discussion may take a few minutes or longer for complex problems.

Start with a straightforward approach, such as brute force, and explain how it works. Then consider whether a more efficient algorithm or data structure could improve it.

Discuss the tradeoffs between possible approaches, including their time and space complexity. Ask whether the interviewer has any specific performance requirements.

Treat this as a collaborative discussion. The interviewer may provide hints to help you reach an acceptable solution.

## 5. Translate Your Algorithm into Code

Once you have a clear plan, begin implementing it in your chosen programming language.

- Explain what you are doing as you code.
- Avoid long periods of silence.
- Break complicated logic into smaller, manageable steps.
- Use meaningful variable names and appropriate functions.
- Check that your implementation matches the algorithm you discussed.

If you discover a problem with your approach, explain what you noticed and how you plan to correct it.

## 6. Test, Analyze, and Optimize

After writing your solution, walk through it using an example and test relevant edge cases.

Explain the time and space complexity of your implementation.

If your solution is not optimal, explain its limitations and discuss how you might improve it. If time permits, implement the improved approach.

If you cannot find a more efficient solution within the available time, be honest about that and explain what you would investigate next rather than claiming that your solution is optimal.

## Key Principle

**A coding interview is not just about writing code. It is about demonstrating how you understand problems, evaluate approaches, communicate your reasoning, and develop correct and efficient solutions.**
